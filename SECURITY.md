# Security Policy

If you find a security vulnerability please report it to us. Thank you for helping keep our users safe!

## Supported Versions

We actively monitor and patch vulnerabilities. The table below outlines which versions of this project currently receive security updates:

| Version | Supported          |
| ------- | ------------------ |
| All public releases   | :white_check_mark: |



## Reporting a Vulnerability

If you find a security vulnerability, **please do not open a public issue.** We take the security of our project seriously but we need time to address potential issues.


### How to Report

To report a vulnerability, please use one of the following channel:

- **GitHub Private Vulnerability Reporting:** Go to the "Security" tab of this repository, select "Advisories", and click "Report a vulnerability".


### What to Include

Please include the following details in your report if possible:

* **Description:** A detailed overview of the vulnerability and its potential impact.
* **Affected Component:** The full paths of source files, specific branches, or versions impacted.
* **Steps to Reproduce:** Step-by-step instructions, a proof-of-concept (PoC), or sample exploit code.


## Our Response Process

Once a report is received, you can expect the following timeline:

* **Acknowledgment:** We will acknowledge receipt of your report within **72 hours**.
* **Triage & Assessment:** We aim to provide an initial assessment and validation within **7 days**.
* **Updates:** We will keep you updated as we work on a fix.
* **Disclosure:** We will coordinate a public security advisory and credit you for the discovery (if desired) once a patch is ready.
