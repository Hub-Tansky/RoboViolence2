# 0040: The first-run box downloads the original BV2 data with the OS's own curl and unzip tools

- Status: Accepted
- Date: 2026-10-29
- Affects: `game/src/DataDirPicker.cpp`, `game/src/DataDownload.cpp`, `bv2::originalDataDir` and `detectDataDir` in `game/src/Paths.cpp`, `packaging/make_deb.py`; Project item "First-run: one-click download of original BV2 data" (owner-approved design, 2026-10-29); supersedes [0033](0033-first-run-dialog-recommends-bv2-zip.md), amends [0016](0016-player-data-lookup-and-package-content.md)

## Context
- Without the original data the game is placeholders only. Windows players failed the ADR 0033 steps (download, unzip, choose the right folder level; Explorer's Extract All adds a nesting level).
- Release builds have no HTTPS client (`BV2_WITH_HTTP` off, [ADR 0002](0002-compile-out-libcurl.md)) and no zip library.
- Every supported OS ships the tools: Windows 10 1803+ has `curl.exe` and `tar.exe` (bsdtar, reads `.zip`) in `System32`; macOS has `/usr/bin/curl` and `/usr/bin/tar` (bsdtar); Linux has `curl` and `unzip`.

## Decision
- The first-run box (owner's text, 2026-10-29) has two buttons: "Download and play" (Enter) and "Use placeholders" (Escape; closing counts the same). No folder dialog; a path field in Options is a separate item.
- "Download and play" runs the OS tools through `SDL_CreateProcess` (`System32` paths on Windows, `/usr/bin` elsewhere; no console window on Windows): `curl` fetches the upstream zip of one pinned commit (`BV2_UPSTREAM_COMMIT`), `tar`/`unzip` extracts only `BaboViolent2/Content/main/`. A small window shows a progress bar; closing it cancels and returns to the box.
- Everything happens in `<pref parent>/original.partial`. The 324 `Content/main` entries of `tools/original-assets.sha256`, compiled in (`OriginalHashes.h`, generated by `game/CMakeLists.txt`), must all match before the folder is renamed to `originalDataDir()` (`%APPDATA%\BaboViolent2\original`, `~/Library/Application Support/BaboViolent2/original`, `~/.local/share/BaboViolent2/original`; inside `BV2_PREF_DIR` when that overrides the pref dir). The folder is saved in `data-dir.txt`; `detectDataDir` checks it first, so a reinstall or a lost `data-dir.txt` reuses it.
- On failure a box offers "Try again", "Open in browser" (the `master.zip` of ADR 0033, whose folder name auto-detect knows) and "Use placeholders".
- The `.deb` depends on `curl` and `unzip`. The `.tar.gz` assumes them; without them the failure box's browser path remains.
- Windows installer unchanged: its Finish page starts the game, which shows this box.

## Consequences
- Supersedes ADR 0033's rejection of downloading the data ourselves and ADR 0016's rejection of copying the data into the user's folder. The project still never redistributes the assets: the player's machine fetches them from the upstream repository.
- A move or rename of the upstream repository, or a new pinned commit, changes `BV2_UPSTREAM_COMMIT` and possibly `tools/original-assets.sha256`.
- The progress bar is relative to a fixed 17 MB, since GitHub's archive responses carry no length.
- "Use placeholders" is still not remembered (ADR 0016): remembering it waits for the Options path field, the way back.
- Rejected: libcurl plus a zip library (a TLS stack and CA bundle lookup to maintain on three OSes); the Windows installer downloading the data (a second implementation for one OS); `master.zip` without a hash check (an upstream push would change what players get, unchecked).
