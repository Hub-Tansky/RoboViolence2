# game

The game: client, listen server, dedicated server and map editor from one codebase. `CONSOLE` selects the headless server (`bv2dedicated`); `bv2` is the client.

- **Entry:** `src/main.cpp`; top-level loop in `src/Scene.cpp`, hosting in `src/SceneNet.cpp`.
- **Simulation:** `Game.cpp` (shared state), `Server*.cpp` (authoritative), `Client*.cpp`, `Player*.cpp`, `Map*.cpp`, `Weapon.cpp`.
- **Wire format:** `src/netPacket.h` (raw structs). Changing a layout needs a `GAME_VERSION_SV/CL` bump (`Server.h`, `Client.h`).
- **Variables:** `GameVar.cpp` registers every `sv_*`/`cl_*` variable.
- **Depends on:** `babonet`, `dko`, `zeven_core` (`zeven_client` for `bv2`), SQLite, libcurl (`BV2_WITH_HTTP`).
- **Autotest:** `bv2 --autotest <script> [--timeout <s>]` runs console commands, `wait <s>`, `expect-console <text>` and `expect-scene intro|menu|loading|game|editor`, one per line; exits 0 only on a pass, 1 on a failed expect, bad script or early quit or init failure, 2 on timeout ([ADR 0025](../docs/decisions/0025-client-autotest-mode.md)). Examples: `tests/autotest/`. `tests/e2e/e2e.py` drives several clients against a dedicated server and master; `refreshgames` requests the master list. `screenshot <name>`, `menutab <tab>` and `scoreboard 0|1` feed the screenshot goldens in `tests/golden/` ([ADR 0026](../docs/decisions/0026-screenshot-goldens.md)); `editorclick open|ok|cancel|pick <map>` drives the editor's Open dialog (`tests/autotest/editor-open.txt`, ROBO-213).
- **Crash report:** the client writes `crash-<start time>.txt` (version, on macOS the load address, signal or exception, stack as module + offset) to the pref dir when it crashes (`src/CrashReport.cpp`); the Debug build's `crash` console command triggers one. Release packages carry no symbols: resolve a report with that tag's symbols, [runbook "Crash reports"](../docs/ops/runbook.md#crash-reports) ([ADR 0048](../docs/decisions/0048-client-crash-report-in-pref-dir.md), [ADR 0051](../docs/decisions/0051-release-symbols-kept-privately-per-tag.md)).
- **Bots:** `sv_bots` (env `BV2_SV_BOTS`) fills the server with bots, connectionless slots run by `src/Bot.cpp` and reconciled by `Server::updateBots` with the rules in `src/BotRoster.cpp`; names in `main/bots/names.txt`. `tests/bot_sim.cpp` plays a seeded bots-only match ([ADR 0049](../docs/decisions/0049-server-side-bots-for-empty-servers.md)).
- **Server file list:** `game/CMakeLists.txt` lists the files that produce code under `CONSOLE`. A file that is empty there (menus, editor, rendering) is left out.

## Gotchas

- Sixteen old-menu `.cpp` files (`MainMenu.cpp`, `Menu.cpp`, `CreateGame.cpp`, ...) were not in the Visual Studio project and are not built. Treat them as dead.
- The package (runtime dir) provides `main/` ([ADR 0005](../docs/decisions/0005-runtime-main-data-root.md)); the build creates `build/<preset>/runtime/`.
- The client finds the player's BV2 data (`BV2_DATA_DIR`, saved folder, auto-detect, first-run download in `DataDirPicker.cpp` and `DataDownload.cpp`, [ADR 0040](../docs/decisions/0040-first-run-downloads-original-data.md)); launch scripts, languages and `bv2.example.cfg` come from the package via `bv2::contentFile` ([ADR 0016](../docs/decisions/0016-player-data-lookup-and-package-content.md)), and the game's own maps (`content/maps`) are read after the pref dir and data root by `bv2::mapFileForRead` ([ADR 0054](../docs/decisions/0054-game-ships-its-own-maps.md)). "Use placeholders" is remembered in `data-dir.txt`, Options → Game assets changes the folder ([ADR 0042](../docs/decisions/0042-game-assets-option-remembers-placeholders.md)); `--placeholders` skips the box for one run.
- The proprietary art pack downloads in the background on start into `bv2::artPackDir()` (`robo_art` beside `original`), checked against the SHA-256 pinned in `ArtPack.cpp`, and stacks over the BV2 data and the base pack; the first run, and the first start after a new pin, waits on a splash for it, up to 60 s (`ArtDownloader.cpp`, [ADR ROBO-260](../docs/decisions/ROBO-260-art-pack-downloads-beside-the-gpl-game.md)). `--no-art-download` turns the download off (remembered as `art-download-off` in the pref dir); `--placeholders` skips it for one run.
- Packs a source build fetched (`-DRV2_ASSETS`) sit in `runtime/packs/` (`bv2::buildPacksDir`, found beside the real folder of the package's `main/`). `bv2::assetPackStack` stacks the build's `url` pack over its `robo_art` (which replaces the downloaded art pack and skips the download) over the data root over the base pack; `detectDataDir` finds `packs/original` right after the pref dir's `original`. `--placeholders` leaves them all out ([ADR ROBO-261](../docs/decisions/ROBO-261-build-option-fetches-game-assets.md)).
- Assets are loaded by id: `bv2::assetPath("models/Rocket")` gives `main/models/Rocket.DKO` from `content/base-pack.tsv`, compiled in; an unknown id is reported and loads nothing ([ADR 0066](../docs/decisions/0066-game-loads-assets-by-id.md)). The player's data folder stacks over the package's base pack: an id resolves to the topmost pack holding its file (`bv2::setAssetPacks`, called in `main.cpp`; [ADR 0069](../docs/decisions/0069-asset-packs-stack-over-the-base-pack.md)). New code asks for an id, never a `"main/` path.
- UBSan on the dedicated server reports member calls on a null `Server` (`Console.cpp:833`, `Server.cpp:1476`); Step 4 fixes them.
